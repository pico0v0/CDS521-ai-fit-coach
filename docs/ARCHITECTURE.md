# 系统架构与代码约定

## 设计原则

1. **AI 模型是视觉感知，不是运动诊断**。真实模式调用 `src/pose.js`，模拟模式调用 `src/simulator.js`，两种模式必须持续显著标注。
2. **算法优先保持纯函数/纯对象**。`src/exercise.js` 不允许依赖 DOM / MediaPipe 包 / 摄像头。这样使用 Node 内置测试即可做回归。
3. **数据最小化**。浏览器 localStorage 只保存训练统计，不能暗中保存录像/截图。未来如需采集视频/关键点数据，必须先获知情同意并说明删除方式。
4. **演示优先保持易运行**。零依赖是本版刻意选择，技术栈不以流行程度决定。若迁移 React，先有实机验收记录和回归测试，再迁移。

## 模块接口

| 模块 | 输入 | 输出 / 副作用 | 注意 |
| --- | --- | --- | --- |
| `pose.js` | 网页视频帧 + timestamp | Google 模型 33 landmarks | 首次联网，真正的 AI |
| `simulator.js` | 训练经过时间 + 动作类型 | 合成 33 landmarks | 非 AI，不能用于评测模型 |
| `exercise.js` | landmarks / 2D angle / timestamp | 有效次数、未达幅度次数、事件 | 核心可测试模块 |
| `draw.js` | landmarks + Canvas | 画骨架 | 绘制不改变模型输入 |
| `app.js` | 用户事件 + 模型输出 | UI、相机生命周期、训练会话 | 今后建议拆分 camera / presentation |
| `store.js` | 训练记录 + 目标 + 疲劳 | localStorage、规则建议 | 不使用网络 |

## 关节角度和状态机

- `angleDegrees(A,B,C)` 返回 [0,180] 度的二维夹角，异常/退化点返回 `null`。
- 目标关节：深蹲分别比较 23-25-27 / 24-26-28；弯举分别比较 11-13-15 / 12-14-16。首版选择更可见一侧。
- 每个动作都经过 `等待站稳 → 已就绪 → 动作进行中 → 达到预设幅度 → 返回起点 → 计数/不计数`。
- 初始演示阈值：深蹲开始 `<142°`、示例底部 `<=110°`、返回 `>=155°`；弯举 `<128°`、`<=65°`、`>=155°`。
- 采用简单指数平滑、动作周期至少 650 毫秒、失去关键点后中断当前周期，长时帧间隔重置周期。
- 以上是为课程展示准备的经验规则，不代表适用于所有人。后续应针对每个机位用真实人工标注做评估。

## 模式一致性

真实模式：`getUserMedia` → `createPoseLandmarker` → `detectForVideo(video,time)` → `extractJointAngle` → `analyzer.update` → UI。

模拟模式：`simulatePose(elapsed,exercise)` → **相同的** `extractJointAngle` → `analyzer.update` → UI。

这样可以在离线时验证 UI、动画、计数状态机及训练记录，但**不能**推断真实模型的识别效果。

## 已知设计限制

- 摄像头和模型推理在主线程中工作，模型调用是同步 API，低性能机器可能卡顿；后续可评估 Worker/降频。
- 左右侧关键点使用每帧置信度选择，可能切换侧别；后续需要训练中锁定一侧并在关键点丢失时重置。
- 未独立做连续几帧确认的专业级运动学控制；现有阈值作为示例基准。
- 不支持多用户/云同步/器械重量自动识别，不支持医学评估。
