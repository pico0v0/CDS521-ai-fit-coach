# 后续开发计划 / 任务清单（必须按优先级推进）

> **项目场景**：AI 基础课小组 20 分钟展示。不要把课堂 Demo 扩成医疗产品或庞大商业平台。下一位 AI 每轮执行一个阶段，打包交审后再推进。

- [x] 真实 MediaPipe 推理接口、摄像头获取和骨架 Canvas 代码。
- [x] 算法单元测试、HTTP 冒烟测试。

## M1 — 第一轮交给下一位 AI：实机 AI 验收（P0 / 必须最先做）

### 任务 M1-01（优先级 1）：实际启动并修复真实模式

**目标**：在有网络的 Chrome/Edge + 摄像头的电脑上能看到视频及真实骨架，角度变化能推动真实深蹲计数。

步骤：
1. 解压后 `npm run dev`，打开 `http://localhost:4173`，进入实时训练。
2. 点击 **启动 AI 摄像头**，记录摄像头授权是否成功，以及 CDN、WASM、`.task` 模型是否能加载。如果失败，保留**原始错误全文**，修复时不要省略报错上下文。
3. 让一个真人侧面全身入镜，观察 skeleton 和 angle 是否随动作变化，并至少做 5 次完整深蹲。
4. 测试关闭摄像头、暂停/恢复、切换弯举、拒绝授权后重试、重复进入训练页。
5. 真机失败则修复；若无法访问真实设备，必须明确标注 `BLOCKED`，不得标成 `PASS`。不能只用模拟模式代替。

**验收**：真实模式能够从视频中产生非空 MediaPipe landmarks，并有带日期、设备、浏览器版本的测试记录。附屏幕截图或经过同意的录像、控制台日志概要（不含隐私素材）；手工对照计数至少一段。如果不满足，不允许直接进入 M2。

### 任务 M1-02：保护状态边界并补回归测试

- 解决在训练过程中切换页面、快速重复点击开始、摄像头拒绝授权、模型加载迟缓时的状态竞争。
- `src/exercise.js` 增加稳定的肢体侧别选择/锁定方案，避免左右腿快速切换造成误判。
- 增加浏览器 Playwright 验证脚本（自行选择工具但不让基础运行变复杂）；至少覆盖首页 → 模拟 → 结束 → 报告 → 重新训练。
- **验收**：`npm run check`、`npm test`、`node scripts/smoke.mjs` 全通过，且有真实浏览器交互验证。

## M2 — 第二轮：提高课堂可靠性（P1）

- [ ] **M2-01 资源可用性**：将受许可允许的固定版本 MediaPipe JS/WASM 和 `.task` 模型资源本地化/缓存，记录来源、版本、SHA256 与许可证；尽量让真实模型在离线环境也能加载，避免 CDN 故障导致演示失败。
- [ ] **M2-02 性能**：记录处理帧率、平均推理延迟；低性能机降频，卡顿时不能计入虚假动作。
- [ ] **M2-03 现场 UX**：摄像头失败提示清楚、姿态可见性不足时暂停计数、机位指引与阈值说明明确。
- [ ] **M2-04 真实录屏**：录制一段经过同意的真实运行视频作为课堂备用（不能用模拟动画替代）。

**验收**：真实设备、浏览器与机位参数记录完整；无未解释的关键性加载失败；清楚区分「已实现」与「未实现」。

## M3 — 第三轮：实验和报告（P1）

- [ ] **M3-01 人工对照实验**：至少 3 人，每人 2 动作、各至少 10 次，采集人工计数与系统计数、设备、机位、光照条件（实验者同意）。
- [ ] **M3-02 测试统计**：计算每组绝对计数误差、典型错误、未达幅度误报/漏报，不要编造百分比。
- [ ] **M3-03 可解释分析**：保留成功、失败、遮挡案例并说明角度误差产生原因。
- [ ] **M3-04 课堂 PPT**：12–15 页，20 分钟，保留 6 分钟真实演示；准备离线/权限故障兜底方案。

**验收**：实验结果可复现，可追溯人工标注；模拟数据绝不混入真实计数准确率。

## P2 选做（必须 M1–M3 核验后）

- 自定义目标阈值与个人基线校准。
- 简易器械教学页面（手动选择器械），规则训练计划。
- 将 UI 迁移到 React + TypeScript，保留算法层 API 和回归测试。
- 新增轻量时序动作分类模型：必须先收集合法、标注充分的数据集，建立训练/验证分集与基线评估；不必为了“使用 AI”重复训练姿态估计大模型。
- Android 原生 App：课程 MVP 不需要。

## 明确禁止的改动

- 不得将合成骨架称为真实 MediaPipe 结果。
- 不得根据摄像头宣称诊断关节损伤、骨盆前倾疾病或预测个人损伤概率。
- 不得虚报准确率、声称测试通过但没有运行证据。
- 不得将 OpenAI/其他平台 API Key 放在前端或压缩包。
- 不得删除 `handoff/HANDOFF_RULES.md` 或绕过统一打包协议。
